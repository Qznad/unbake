Contribute

Help build unbake

unbake is written in Rust, with Demucs and Basic Pitch run as outside programs. Ideas, bug reports, test songs and code are all welcome. Open an issue first if you plan something big, so we can talk it through.

unbake is under the MIT license, and contributions are accepted under the same license.

Open problems

The lead melody

Demucs puts every instrument that isn't drums, bass or vocals into one "other" stem, and Basic Pitch hears maybe half of a busy lead in it. unbake picks the loudest note per step, votes across the song's repeats, and tidies the line, but the lead is still often wrong. Better separation of the lead, or a transcriber that copes with mixed stems, would help most.

Automation clips

Filter sweeps and fades are everywhere in electronic music, and unbake can't write them yet, so agents have to ask the user to draw them. This means working out how FL Studio stores automation clips in a .flp and adding them to compose.

macOS

The listening side runs anywhere, but reference sounds, sample search and rendering look for FL Studio's Windows folders. FL Studio's folders on macOS differ, and nobody has tried them yet.

More kinds of music

unbake assumes 4/4 on a straight 16th-note grid, and it has been tuned on a handful of electronic instrumentals. Swing, triplets, other meters and sung melodies all need work, and songs to test them on.

Set up

Follow Install to get the tools, then:

git clone https://github.com/Qznad/unbake
cd unbake
cargo build --release
cargo test

Before a pull request, these should all pass:

cargo test
cargo clippy
cargo fmt --check

Clippy should give no warnings. The test songs aren't in the repo, since they're copyrighted, so the tests build their own audio and projects.

Code style: every function has exactly one short lowercase comment line above it saying what it does, and there are no other comments.

While an agent runs the MCP server, Windows locks unbake.exe and cargo build fails. Point your .mcp.json at a copy of the exe to avoid it.

Where things live

AreaFiles in src/
Listeninganalysis/ (tempo, onsets, drums, pitch, key, chords, sections), separate.rs (Demucs), basic_pitch.rs, findings.rs and evidence.rs (each result with its confidence and unknowns)
Reading the songviews.rs (overview, grids, harmony, repeating parts), song_map.rs (the section timeline), listen.rs (levels, what a stretch sounds like), clues.rs (signs of delay, reverb, pumping), drum_sounds.rs (matching drum samples to the song's hits)
Writing projectsflp/ (the FL Studio project reader and writer), compose.rs (a project from a JSON description), combine.rs (section loops into one song), rebuild.rs (the note-for-note pipeline)
Checkingcheck.rs (notes against what the song plays), render.rs and compare_render.rs (render through FL Studio and compare with the stems), eval.rs (score against a real project)
Agentsmcp.rs (the MCP server), tools.rs, doctor.rs, and skills/unbake/SKILL.md, the workflow the server sends to every agent

Measuring a change

Music is easy to fool yourself about, so say what you measured and on which songs. unbake eval scores a rebuild against a real FL Studio project of the same song: drums, bass, melody, chords and patterns. If you have FL projects of your own songs, they make the best test cases.
